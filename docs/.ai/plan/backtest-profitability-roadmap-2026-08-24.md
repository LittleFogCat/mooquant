## 一、现状诊断：为什么回测经常是负收益

### 1.1 结论先行

> **负收益大多是"真实且正确"的，不是 bug**——在 A 股日线级别，当前这组策略（全仓进出、无止损、无市场状态过滤、简单技术信号）+ 现实交易成本（约 0.3%/往返）的组合，数学期望本身就是负的。`数据源回落 mock 随机游走` 进一步把"偶尔负"变成"经常负"。

根因按影响排序：

| 层级 | 根因 | 严重度 | 性质 |
|---|---|---|---|
| 策略结构 | 全仓 all-in/all-out、无止损/止盈、无 regime 过滤、无仓位管理 | ★★★★★ | 结构性 |
| 交易成本 | 0.3%/往返成本 vs 日线微弱信号 alpha，交易越多亏越多 | ★★★★★ | 结构性 |
| ML 链路 | 标签与执行时间结构脱节、无概率校准、无置信度→仓位映射、margin 判决粗糙 | ★★★★ | 设计缺陷 |
| 数据降级 | 无 miniQMT 时回测在**随机游走** mock 数据上运行（无漂移→期望收益 0 减成本=负） | ★★★★ | 触发场景 |
| 数据/样本 | 单标的、单段历史、默认区间恰为下行市、样本内回测仅警告不禁用 | ★★★ | 结构性 |
| 评估指标 | 短区间年化失真、持仓最后浮盈亏不计入胜率、缺成本敏感性/参数敏感性 | ★★ | 工程缺陷 |

### 1.2 逐条代码级证据

**A. 策略结构问题（最根本）**

1. `bridge/strategies/builtin/ma_cross.py`：金叉全仓买、死叉全仓卖。震荡市反复假信号，每轮往返 ~0.3% 成本被反复收割。
2. `bridge/strategies/builtin/momentum.py`：`ret > threshold(3%)` 才买（**追高**），`ret < -3%` 才卖（**卖点滞后**），系统性地"买在 3% 涨幅后、卖在 3% 跌幅后"→ 买高卖低，负期望是数学必然。
3. `bridge/strategies/builtin/mean_reversion.py`：跌破均线 3% 买、涨过均线 3% 卖，**无止损**。单边下跌市里买入后一路套牢，可能永远等不到卖出信号。
4. 三者共同点：无止损/止盈/时间止损、无市场状态过滤、无仓位管理。执行侧（`backtest_engine.py:397-458`）把 buy/sell 都按**全仓**处理（`max_qty = int(cash / (price*(1+cost)))` 全资金买入；卖出全仓）。

**B. 交易成本是决定性的**

- `backtest_engine.py:224-229`：佣金 0.03%×2 + 印花税 0.05%（卖出）+ 过户费 0.001%×2 + 滑点 0.1%×2 ≈ **0.30%/往返**。
- 单标的日线信号，可捕捉的 alpha 通常远小于 0.3%/往返 → **任何"交易频繁的简单策略"在 A 股日线上都必然净亏损**。这不是参数问题，是结构问题。
- 最小佣金 5 元（`_commission_of`）在小资金下占比放大。

**C. ML 链路设计缺陷**

1. **标签与执行脱节**（`training/labels.py` + `builtin/lstm_trend.py`）：标签是"未来 5 日收益率 > 阈值"，但策略拿到 buy 信号后**无限期持有直到出现 sell 信号**，与模型预测的 5 日窗口完全不对应。模型的微弱预测力被错误的时间结构浪费。
2. **三分类 margin 判决太粗糙**（`lstm_trend.py:36-49`）：`prob_up > prob_flat + margin and prob_up > prob_down + margin`。不触发=不交易；触发时往往是模型过度自信的时刻。没有"期望收益 = 概率 × 预期幅度 − 成本"的决策语义。
3. **无概率校准**：softmax 概率 ≠ 真实胜率，margin=0.05 没有任何可解释性。
4. **strength 未用于仓位**：`strength=prob_up` 只作展示，回测仍是全仓（`backtest_engine.py` 不消费 strength）。
5. **模型 zoo 弱且单一**：只有 LSTM/MLP/Transformer 三个深度模型，无表格基线（LightGBM/XGBoost），无集成。小样本日线数据上深度模型极易过拟合/退化（知识库 0401 已记录"退化为单边预测"是 ML 固有限制）。
6. **无 walk-forward / 超参搜索**：window/horizon/threshold/margin/架构超参全凭默认值和手调，无稳健性验证。样本内调出的"好参数"换个区间就失效。

**D. 数据降级触发场景**

- `backtest_engine.py:240-247`：真实数据拉不到就回落 `generate_mock_bars`（`_shared.py`：日波动 2% 的**无漂移随机游走**）。在无漂移随机游走上，任何策略期望收益 = 0 − 成本 = **必然为负**。
- UI 已有红色警示条（v0.1.19 链路打通），但用户可能未注意，或根本未连 miniQMT 就习惯性点回测。

**E. 样本与区间**

- 默认回测区间 2024-01-01 ~ 2024-06-30（`backtest_engine.py:221-222`），该区间 A 股多数标的基准（benchmarkReturn）本身为负。
- 单标的单段历史；样本内回测仅 `inSampleWarning` 警告、不禁用（`backtest_engine.py:609-627`）。
- 数据缓存（`db.py` SQLite）如果拉到的是**未复权或旧口径**的历史数据，与训练口径不一致会导致特征漂移（OOD 防御已加，但只告警不阻断）。

**F. 评估指标口径问题**

1. 年化收益率 `annual_return = (final/initial)^(252/days) - 1`（`backtest_engine.py:485`）：**days 为区间 bar 数，短区间（如 1 个月 ≈20 根）年化被放大 12 倍**，数字严重失真。
2. `win_rate`/`avg_hold_days` 只统计**已平仓**交易（`backtest_engine.py:563-569`），最后未平仓的浮盈亏不计入，结果偏乐观/偏悲观取决于收尾方向。
3. 无成本敏感性、无参数敏感性、无逐笔收益分布、无与基准的逐日对比曲线——用户只看到一个负的 totalReturn，无从判断"是真不行还是算错了"。

### 1.3 一个必须澄清的乐观偏差

- 当前撮合是**信号 bar 收盘价生成信号、同一根 bar 收盘价成交**（`backtest_engine.py` 信号循环与撮合循环用同一 `bars`）。真实世界无法"看到收盘价再以收盘价成交"，更现实的假设是**次日开盘成交**。
- 因此：**当前负收益还不是最悲观的**。若改为保守撮合（次日开盘），回测会更难看；若改为激进撮合（盘中触发、收盘价无滑点），会更好看。**必须先统一"撮合口径"再谈策略优化**，否则所有调优都是在错误的标尺上跳舞。

## 二、工业化目标与验收标准

> 从"能跑"到"可信、可复现、可对比、可实盘、可盈利"。核心转变：**回测的目的不是"好看"，而是"对实盘的预测足够准"。**

### 2.1 量化验收标准（商业化底线）

| # | 标准 | 现状 | 目标 |
|---|---|---|---|
| 1 | 同一配置重复回测 100% 一致 | ✅ 已满足（确定性） | 保持 |
| 2 | 训练/回测/实盘数据单一口径 | ✅ datafeed 已统一 | 保持 + 信号路径指纹校验 |
| 3 | 每个模型出厂带样本外体检报告 | ✅ health_report 已有 | 升级：组合级样本外 + walk-forward |
| 4 | 撮合口径显式可选（收盘/次日开盘/tick） | ❌ 仅收盘价 | 三档可切换 + 默认次日开盘（保守） |
| 5 | 回测含成本敏感性 + 参数敏感性 | ❌ | 一键生成，可写进报告 |
| 6 | 回测默认做时间隔离（训练区间外） | ⚠️ 仅警告 | 默认禁止样本内回测，需显式勾选 |
| 7 | 组合级回测（多标的） | ❌ 单标的 | 多标的 + 资金分配 + 分标的贡献 |
| 8 | 关键路径回归测试 | ✅ 71 个单测 | 保持 + 新增敏感性/walk-forward 测试 |
| 9 | 实盘 vs 回测偏差可追踪 | ❌ | paper trading 日志 + 跟踪误差报告 |

## 三、全方位优化路径（按依赖排序，每阶段可交付可验证）

### D0 · 正确性加固（先让"负收益"可信，约 1 周）

> 原则：**在把策略变好之前，先确认当前数字是"算对了的"**。任何调优若建立在错误标尺上都是浪费。

**D0.1 撮合口径三档化（最高优先）**
- 引擎新增 `fillModel: "close" | "next_open" | "tick"`：
  - `close`：当前行为（信号 bar 收盘成交，乐观）
  - `next_open`：信号在 bar i 收盘生成，**次日开盘**成交（保守，默认推荐）
  - `tick`：预留日内撮合（需分钟数据）
- UI 回测配置暴露该选项 + 默认 `next_open`，并明示"当前撮合口径"。
- 同时暴露成本假设的敏感性（一键 0.5×/1×/2× 成本对比）。

**D0.2 指标口径修复**
- 年化收益率：当 `days < 60` 时不年化或标注"区间过短，年化仅供参考"；统一用自然日/252 口径并标注。
- 胜率/盈亏比：把**未平仓持仓的浮动盈亏**纳入"已实现+未实现"口径（提供 `pnlRealized` 与 `pnlTotal` 两个版本）。
- 收益曲线补充：逐笔盈亏分布、持仓时长分布、月度热力图（已有 monthlyReturns，UI 补图）。

**D0.3 阻断静默降级**
- mock 数据回落时：回测**默认拒绝执行**（提示"未连接 miniQMT，无法获取真实数据"），仅当用户显式勾选"允许使用模拟数据"才执行，且结果页强制红条 + 结果文件打 `dataSource: "mock"` 水印。
- 训练路径已不回落 mock，保持一致。

**D0.4 缓存口径校验**
- `db.py` 缓存读取前校验 `dividend_type` 与 `DATA_SPEC_VERSION`；缓存数据与当前口径不匹配时**忽略缓存重新拉取**，避免旧口径数据污染。

### D1 · 数据地基（组合化的前提，约 1-2 周）

> 原则：**组合 > 单标的；全市场 > 单标的**。单标的回测本质上是在赌个股，而工业化量化是"吃组合的期望"。

- **全市场日线落库**：把 SQLite 单表升级为**按日增量更新的全市场 bar 库**（数据量大后用 DuckDB/Parquet，单文件、列式、SQL 查询、零运维），支持全市场横截面特征与组合回测。
- **指数/行业数据**：沪深300、中证500、行业指数、涨跌家数 → 提供"市场状态特征"（regime）。
- **基础信息表**：上市日期、退市日期、ST 标记、流通股本（换手率特征前提）、板块 → 停牌/次新/ST 过滤。
- **数据质量监控**：每日取数后跑 `validate_bars` + 覆盖率报告（缺多少标的、缺多少天），异常告警。
- **数据版本管理**：bar 级指纹 + 取数日期戳，回测/训练可复现（"这次回测用的是哪个版本的数据"）。

### D2 · 策略执行与风控层（把规则策略"工业化"，约 1-2 周）

> 原则：**先给策略装上安全带，再谈策略本身**。这一步是"从负收益到正收益"性价比最高的一步。

**D2.1 风控原子层（进引擎核心，所有策略自动获得）**
- 止损：ATR 止损（默认 2×ATR14）或固定百分比（默认 -5%），逐 bar 检查。
- 止盈/时间止损：达到目标或持有 N 日（默认 10）无进展则退出。
- 最大单笔亏损、最大连续亏损熔断（触发后停止开新仓 N 日）。
- **实现位置**：不进策略，放在撮合层做**统一风控封装**（策略 on_bar → 风控层 → 订单），保证回测与实盘同一套风控。

**D2.2 仓位管理**
- 全仓 → 波动率目标仓位：`仓位 = 目标年化波动(如 15%) / 标的年化波动`（ATR 估算），单标的上限（如 20%）。
- `strength` 消费：ML 信号按概率强度线性/分段映射仓位。
- 分批建仓/减仓（如分 3 批）。

**D2.3 市场状态过滤（regime filter）**
- 新增内置 `regime` 工具：大盘（沪深300）在 20 日均线上且自身在 20 日均线上时才允许做多；否则空仓（现金）。
- 与周期无关、可叠加到任何策略；这是"只在顺风时交易"的最简单实现。

**D2.4 组合化**
- 打通 `PortfolioSignal` 路径（`base.py` 已有接口，引擎未实现）：多标的等权/风险平价持仓，周期调仓（如每周）。
- 组合级净值、分标的贡献分解、相关性矩阵。
- **优先做多标的等权组合**：这是散户能吃到的最简单、最稳健的"市场 beta + 微小 alpha"结构。

### D3 · ML 建模工业化（约 2-4 周）

> 原则：**特征决定上限，模型逼近上限；先用稳健的表格模型建立基线，再谈深度模型**。

**D3.1 特征工程**
- 横截面因子：动量（1/3/6 月）、反转（5/20 日）、波动（20 日年化）、流动性（换手/量比）、相对强弱（vs 指数）。
- 市场状态特征：指数趋势、涨跌家数比、市场波动率。
- 特征注册表（`features.py` 已雏形）：每个特征=函数+元数据（依赖列/最小长度/是否尺度不变），UI 可勾选。
- 保留 global 归一化 + OOD 防御（已实现）。

**D3.2 标签工程**
- triple_barrier（已有）+ **meta-labeling**（Lopez de Prado）：第一层模型输出方向，第二层模型预测"该方向信号是否值得执行"→ 过滤低质量信号，直接提升交易侧性价比。
- 标签分布预检：任一类 <10% 或 >70% 时 UI 警告并建议调参。

**D3.3 模型 zoo**
- **LightGBM/XGBoost 作为默认推荐基线**：表格特征（窗口统计 + 因子）下 CPU 友好、小样本不易过拟合，通常显著优于小 LSTM。
- LSTM/Transformer 保留作为时序备选；集成（bagging/stacking）作为进阶。
- 增加内置「稳健日线」训练预设：LightGBM + ATR 三重障碍 + 尺度不变特征 + walk-forward。

**D3.4 训练流程**
- **walk-forward 训练**：滚动窗口（train 2y → test 6m，步进 6m），输出逐段指标稳定性（均值/方差），方差大 = 过拟合信号。
- **时间隔离强制**：默认回测区间必须完全在训练区间之外；重叠需显式确认。
- 概率校准：temperature scaling / isotonic（验证集拟合），让"概率 0.7"真的是 70% 胜率 → margin 参数才有意义。
- 超参搜索：**Optuna**（贝叶斯）+ walk-forward 稳健性评分作为目标函数，禁止在单段样本内调参。
- 随机种子固定 + config 记录（已有 seed 需求，补实现）。

**D3.5 决策语义升级（关键）**
- 从"三分类 margin 判决"改为**期望收益决策**：
  `signal_value = P(up) × E[up_size] − P(down) × E[down_size] − cost_per_roundtrip`
  只有 `signal_value > 0` 才交易，且仓位正比于 signal_value。
- 这直接解决"标签与执行脱节"：期望收益天然对齐交易成本与持有周期。

### D4 · 回测基础设施工业化（约 2-3 周）

> 原则：**回测要能回答"这策略是真行，还是刚好在这个参数/这个区间行"。**

**D4.1 多标的组合回测引擎**
- 引擎支持 `symbols` 列表（当前单标的抛错）+ 资金分配策略 + 组合净值 + 贡献分解 + 换手率统计。

**D4.2 稳健性工具箱（防过拟合核心）**
- **成本敏感性**：成本 ×0.5/×1/×2 三档对比，成本翻倍收益仍正 → 策略鲁棒。
- **参数敏感性**：邻近参数集（±20%）热力图，邻域内大多正收益 → 非参数巧合。
- **时间切片稳定性**：按年/半年分段收益，看是否依赖某一段。
- **walk-forward 回测**：ML 策略按时间段自动切换对应段模型。
- **置信区间**：对交易序列做 bootstrap 收益置信区间。

**D4.3 回测结果管理**
- 已有持久化（`data/backtest_results/`）→ 升级为**结果数据库 + A/B 对比页**：同策略不同参数、不同策略同区间，并排对比。
- 每次回测自动产出**报告快照**（配置 + 指标 + 敏感性 + 净值图数据），支持导出 PDF/分享。

### D5 · 周期与频率（约 1-2 周，与 D2-D4 并行）

> 原则：**周期是策略 alpha 的重要维度，但必须与交易成本、T+1 制度、容量匹配**。

| 周期 | 适配策略 | 成本压力 | 备注 |
|---|---|---|---|
| 日线 1d（当前） | 组合轮动、月度调仓、趋势 | 低 | 主战场，先把日线组合做正 |
| 周线 1w/月线 1mon（已有聚合） | 低频轮动 | 极低 | 已有聚合逻辑，直接可用 |
| 分钟级 30m/60m | 日内动量、T+0 品种（ETF/可转债/期货） | 高 | A股 T+1 限制日内卖出，优先做"T+0 品种"或"尾盘买次日卖"的隔夜策略 |
| 事件驱动 | 财报、涨停板、龙虎榜 | 中 | 需事件数据源，中期再上 |

- **低频优先**：在日线组合策略稳定为正之前，不要上高频。成本是高频的头号杀手。
- 周期作为**策略参数**而非引擎硬编码：`ctx.period` 已支持，补齐多周期数据管道（datafeed 已支持 1m/5m 拉取）。

### D6 · 工具链与工程化（持续）

| 领域 | 现状 | 目标工具 |
|---|---|---|
| 数据处理 | SQLite 单表 + 手写循环 | DuckDB/Parquet + pandas 向量化（取数/清洗/聚合） |
| 回测 | 自研逐 bar 引擎（正确但慢） | 保留自研（保证与实盘共用 on_bar），内部向量化热点；评估期参考 vectorbt/backtrader 做交叉验证 |
| 因子分析 | 无 | alphalens（因子 IC/分组收益） |
| 指标校验 | 手写 indicators | TA-Lib 交叉验证（等长序列对齐测试） |
| 建模 | 裸 torch | LightGBM + scikit-learn Pipeline + Optuna + （可选）PyTorch Lightning |
| 实验管理 | 手写 JSON | MLflow 或轻量本地实验库（记录 config/指标/图） |
| 绩效报告 | 手写 metrics | quantstats/pyfolio 风格报告（含敏感性图） |
| 测试/CI | 71 单测 | 保持 + 新增敏感性/walk-forward/组合回测测试 |
| 模型服务 | http.server 单进程 | 保持（本地单用户够用），补 /health 细粒度 + 启动自检 |

### D7 · 商业化盈利模式（在 D2-D4 稳定后启动）

> 原则：**先证明"回测可信"，再证明"策略有正期望"，最后才谈变现**。任何盈利模式都建立在真实可验证的 alpha 之上。

**D7.1 产品化路径**
1. **自营小规模实盘（paper → 小资金 → 规模资金）**：paper trading 记录 3-6 个月，对比回测/实盘偏差（滑点、成交率、延迟），跟踪误差 < 阈值后才放大资金。
2. **策略集市**：支持用户/团队共享策略（现有策略注册/导出机制扩展为市场），可作为增值功能。
3. **信号订阅/策略即服务**：对验证过的策略提供信号订阅（类似现有 QMT 壳策略的 HTTP /signal 商业化）。
4. **工具增值**：作为 QMT 用户的"建模+回测+体检"增值工具（卖工具而非卖收益），合规且可持续。

**D7.2 风控合规底线（实盘必需）**
- 单标的仓位上限（如 10-20%）、行业集中度上限。
- 最大回撤熔断（如 15% 停止开新仓）、每日最大亏损熔断。
- 实盘日志全留痕（订单/成交/信号/偏差），可审计。
- 交易频率限制（避免对市场造成影响 / 合规刷单）。

**D7.3 盈利的 KPI 定义（避免自欺）**
- 组合级夏普 > 1（样本外）
- 最大回撤 < 20%（组合级）
- 成本翻倍后仍正收益
- 参数邻域 >70% 正收益
- 实盘 vs 回测年化偏差 < 5%（绝对值）
- 连续 3 个 walk-forward 段正收益才允许上实盘

## 四、落地路线图

```
Phase A  正确性（1周）       D0.1-D0.4：撮合口径三档、指标修复、阻断 mock 静默、缓存校验
Phase B  可信度（2-4周）     D2 风控层+仓位+regime+组合化；D4.2 敏感性/切片/walk-forward
Phase C  竞争力（1-2月）     D1 全市场数据；D3 特征/标签/meta-labeling/LightGBM/Optuna/校准
Phase D  商业化（持续）      D4.3 结果管理+A/B；D6 工具链；D7 paper trading→实盘→变现
```

**依赖关系**：
```
D0（标尺可信）→ D2（安全带）→ 让"负收益"先转正（组合+regime+风控+低频）
                      ↓
D1（全市场数据）→ D3（ML 工业化）→ D4（稳健性验证）→ D7（实盘/变现）
```

**关键节奏建议**：
1. **第一优先级 = D0（标尺可信）**：撮合口径三档、指标口径、阻断 mock 静默降级、缓存校验。在把策略变好之前，先确认当前数字"算对了"，否则任何调优（包括 D2 的风控效果）都无法判断对错。
2. **第二优先级 = D2（安全带）**：风控 + regime + 多标的等权 + 低频。这四件事的组合，即使不碰 ML，也有最高概率把"经常负"变成"围绕基准小幅波动/转正"，且改动集中在引擎层、复用性最高。
3. **第三优先级 = ML 升级（D3）**：放到 D0/D2 之后，避免"用不可信的标尺调深度模型"。

## 五、风险与取舍

| 风险 | 应对 |
|---|---|
| 日线方向预测信噪比极低（知识库已记录），深度模型易退化 | 用 LightGBM 基线 + 体检报告 + 组合级评估诚实暴露；不承诺收益，先承诺"可信" |
| 组合回测改动撮合核心，风险高 | 放 D2 最后，先保单标的正确性；保留单标的模式兼容 |
| 保守撮合（次日开盘）让回测更难看 | 正是目的——拒绝虚假繁荣；用"回测保守+实盘一致"建立信任 |
| 引入 DuckDB/LightGBM/Optuna 新依赖 | 均为 pip 单包、无 GPU 依赖、CPU 可用；不可用时优雅降级（延续现有 torch 可选模式） |
| 调参导致样本内过拟合 | 全部调参强制走 walk-forward + 敏感性 + 时间隔离，参数搜索目标函数用稳健性评分 |
| mock 阻断可能让无 QMT 用户无法回测 | 显式"允许模拟数据"开关 + 强水印，不静默 |
