# 建模与回测模块商业化优化计划

> 状态：待评审
> 日期：2026-08-20
> 前置：已修复「回测无交易」根因（训练与回测 volume 单位/复权口径不一致，见 0101-architecture.md 附录）
> 版本基线：v0.1.15

## 目标

把现在的「能跑」升级为「平稳运行 + 有一定可信度」的本地建模与回测工具。分四个阶段（M1→M4），每个阶段都是可交付、可验证的闭环，避免一次性大重构。

**验收总标准（商业化底线）**：
1. 同一配置重复回测结果 100% 一致（确定性）
2. 训练/回测/实盘三端数据口径单一来源（单一 fetcher）
3. 每个模型出厂自带「样本外体检报告」，没有报告的模型不允许被激活
4. UI 上任何数字都有出处，任何失败都有可读的错误提示
5. 关键路径有回归测试覆盖，改代码不靠手测

---

## M1 数据地基（正确性优先，约 1 周）

**原则：模型的上限由数据决定，先修数据再谈模型。**

### M1.1 统一数据访问层（最高优先级）

**现状问题**：同一份行情有 4 条获取路径（trainer / backtest_engine / model_server / qmt_server），各自处理单位、复权，本次 bug 即源于此。

- [ ] 新建 `bridge/data/datafeed.py`：唯一的取数入口 `fetch_bars(symbol, period, count_or_range, dividend_type)`
  - 内部统一：volume=股（×100）、dividend_type 默认 front、代码格式转换
  - 全部现有调用方（trainer、backtest_engine、model_server /signal、executor）改为依赖此模块
  - 训练时把 `datafeed` 的口径指纹（volume 单位、复权方式、字段列表）写入模型 config.json，加载模型时校验指纹，不匹配直接报错而非静默漂移
- [ ] mock 数据生成器（`_shared.generate_mock_bars`）也走 datafeed，并给 mock bars 打 `is_mock` 标记，回测结果中显式标注
- [ ] 删除 4 处重复的取数逻辑（迁移完成后）

### M1.2 数据质量校验

- [ ] `datafeed` 内置校验：缺列、零价、OHLC 交叉（high<low）、停牌长缺口、复权跳变检测
- [ ] 校验失败返回结构化错误（哪只股票、哪一天、什么问题），UI 可展示
- [ ] 训练前打印数据体检摘要：日期范围、有效 bar 数、涨跌停 bar 占比、缺失天数

### M1.3 数据持久化增强（db.py）

- [ ] SQLite 缓存支持按日期范围增量更新（现有 `get_latest_date` 已有雏形）
- [ ] 训练用大数据集（全市场日线）落库，避免每次训练重新拉取
- [ ] 增加 `data/market/` 指数数据缓存（用于后续特征与基准对比）

### M1.4 涨跌停与停牌处理（A股正确性）

- [ ] datafeed 提供涨跌停判定（基于前收盘 ±10%/±20%/±5% 规则，按板块）
- [ ] 回测撮合：涨停不得买入、跌停不得卖出（当前引擎会以收盘价成交，虚增收益）
- [ ] 停牌 bar 不生成信号

## M2 回测引擎升级（可信度优先，约 1-1.5 周）

**原则：回测的意义是「不出假阳性」，宁可少赚也不能虚报。**

### M2.1 交易成本与撮合真实性

- [ ] 最小价格变动（tick 0.01）取整、单笔最小佣金 5 元
- [ ] 成交量约束：成交量不足以吃满仓位时按比例成交（当前全仓假设）
- [ ] T+1 制度：当日买入不可当日卖出（当前引擎允许，A股日线下会虚增收益）
- [ ] 印花税/过户费已有（M2 早期做过了），确认 UI 暴露完整参数

### M2.2 绩效指标补全

- [ ] 索提诺比率、卡玛比率、年化波动率、平均持仓天数、最大连续亏损次数
- [ ] 月度收益热力图（回测 UI 已有 equity curve，补充）
- [ ] 与基准（沪深300）对比曲线，而非只有区间涨幅一个数字
- [ ] 交易分布统计：持仓时长分布、单笔盈亏分布直方图

### M2.3 回测防过拟合

- [ ] **训练/回测时间强制隔离**：模型 config 记录训练数据日期范围；回测时若区间与训练区间重叠，结果页顶部显著警告「样本内回测」（最好直接默认禁止，需用户显式勾选）
- [ ] walk-forward 支持（见 M3.4，回测引擎侧预留分段接口）
- [ ] 回测结果持久化：`data/backtest_results/{id}.json`（含完整配置快照 + 结果），支持历史对比与 A/B

### M2.4 多标的组合回测

- [ ] 引擎支持 symbols 列表（当前单标的限制，多标的抛错）
- [ ] 资金分配策略：等权 / 信号强度加权
- [ ] 组合级净值曲线与分标的贡献分解

## M3 建模升级（约 2 周，与 M2 可并行）

**原则：特征决定上限，模型只逼近上限；先穷尽特征工程，再谈深度模型。**

### M3.1 特征工程 2.0

- [ ] **尺度不变特征**（根治本次 bug 这类问题）：`log(volume)`、收益率序列、价格相对 MA 偏离度，替代裸 close/volume
- [ ] 截面特征：标的收益率相对指数/行业的超额收益（需要 M1.3 指数数据）
- [ ] 特征库扩充：ATR、OBV、换手率（需流通股本数据，可先降级为量比）、振幅、跳空缺口
- [ ] FeatureBuilder 重构为「特征注册表」：每个特征是独立函数 + 自描述元数据（名称/依赖列/最小历史长度），`n_features` 自动推导，UI 可勾选
- [ ] 归一化改进：global z-score 保留，但统计量改为「训练期截至日期内」统计并持久化（当前全量统计含验证期，有轻微前视）；纯收益率/log 特征可免归一化

### M3.2 标签工程 2.0

- [ ] triple_barrier 升级：波动率自适应障碍（ATR 倍数替代固定百分比），适应不同波动率的标的
- [ ] 标签分布预览：训练前展示三类占比，过偏（任一类 <10% 或 >70%）时 UI 警告并建议调阈值
- [ ] meta-labeling（进阶，可选）：第一层模型出方向，第二层预测「该信号是否可靠」过滤低质量信号

### M3.3 模型与训练流程

- [ ] 模型 zoo 扩充：GRU、CNN-1D（时序卷积基线）、LightGBM（表格特征强基线，CPU 友好，装包即用）
  - LightGBM 作为**默认推荐**：小数据量（几千样本）下通常显著优于 LSTM，且不易退化
- [ ] 训练配置模板：内置「稳健日线」预设（LightGBM + ATR 三重障碍 + 尺度不变特征）
- [ ] 早停指标可选（val_loss / val_accuracy / F1-macro），防止 loss 下降但单边押注
- [ ] 类别不平衡策略显式化：class weight / focal loss / 采样三种可选，默认 class weight
- [ ] 随机种子固定 + 训练结果可复现（config 里记录 seed）
- [ ] 每次训练自动产出**样本外体检报告**（核心卖点）：
  - 训练/验证曲线图
  - 混淆矩阵 + 分类别 precision/recall
  - 概率分布直方图（本次问题若是 UI 可视化，一眼就能看出退化）
  - 简单回测 smoke test（训练区间外 3 个月，产出交易数/收益）
  - 「模型质量评分」：综合 accuracy/F1/信号触发率/是否退化单边，红黄绿三档；不合格模型标记 `degraded`，禁止激活

### M3.4 Walk-forward 训练（防过拟合核心）

- [ ] `walk_forward()` 训练器：滚动窗口（如 train 2y → test 6m，步进 6m）逐段训练+评估
- [ ] 输出逐段指标稳定性（各段 accuracy/收益的均值与方差），方差大 = 过拟合信号
- [ ] ML 策略支持「walk-forward 模式」：回测时按时间段自动切换对应段模型（防用未来数据训练的模型回测过去）

### M3.5 概率阈值策略改进

- [ ] margin 参数改为「期望收益阈值」语义：用模型概率 × 标签阈值估算期望收益，高于成本（手续费+滑点）才触发，比裸 margin 更可解释
- [ ] 可选：概率校准（temperature scaling，用验证集拟合），让 0.7 的概率真的是 70% 胜率

## M4 工具化与 UI 易用性（约 1-1.5 周，随 M1-M3 渐进交付）

**原则：用户不需要懂代码也能走完「选数据 → 训练 → 体检 → 回测 → 对比」全流程，且每步知道自己在做什么。**

### M4.1 训练流程引导

- [ ] 训练表单加「高级选项」折叠区（默认收起），基础模式只露：标的、周期、标签类型、架构（含推荐标记）
- [ ] 训练前 dry-run 校验：拉数预检（数据量够不够、标签分布、特征数），不通过给人话提示，而不是训练完才发现
- [ ] 训练进度增强：显示 epoch 曲线（实时 loss/accuracy 小图）、ETA
- [ ] 训练完成弹「体检报告」（M3.3 的产出）而不是一行「训练完成」

### M4.2 模型管理增强

- [ ] 模型列表加质量评分徽章（红黄绿）+ 关键指标列（accuracy/F1/样本外收益）
- [ ] 模型详情页：config 全览、训练曲线、混淆矩阵、概率分布图（历史训练的 train_log 已存，补 UI）
- [ ] 模型对比视图：选 2-3 个模型同图对比样本外表现
- [ ] 激活模型时的守门：degraded 模型激活需二次确认

### M4.3 回测 UI 增强

- [ ] 回测配置摘要卡片：回测前明示「数据源、复权方式、成本假设、训练/回测区间是否隔离」
- [ ] 回测历史记录页（依赖 M2.3 持久化）：同策略不同参数 A/B 对比表
- [ ] 失败信息人话化：`回测数据不足` → `600036 在 2024-01-01 至 2024-03-01 仅 0 根K线（可能未上市或数据源缺失）`

### M4.4 稳定性与工程化

- [ ] model_server 健康自检：torch 可用性、数据目录可写、端口占用，/health 返回细粒度状态
- [ ] 训练任务队列：当前并发训练会互相干扰（pipeline 无队列），加串行队列 + 排队状态
- [ ] Python 桥进程守护：崩溃自动重启（带指数退避），UI 显示桥状态
- [ ] 日志分级落盘：data/logs/ 按模块分文件，出错可一键导出诊断包
- [ ] 打包发布前 smoke test：`npm run dist` 产物在新环境跑 45 个单测 + 端到端训练/回测冒烟

```
M1.1 datafeed ──→ M1.2/M1.4 校验 ──→ M2 回测升级 ──→ M2.4 多标的
     │
     └──→ M3.1 特征 2.0 ──→ M3.3 模型 zoo + 体检报告 ──→ M3.4 walk-forward
                │                                              │
                └──→ M3.2 标签 2.0                    M4.2 模型管理（消费体检报告）
                                                              
M4.1/M4.3/M4.4 随各阶段渐进交付
```

建议节奏：M1 全部 → M2.1-M2.3 → M3.1-M3.3 → M4 补齐 → M2.4/M3.4/M3.5（增强项）。

## 风险与取舍

| 风险 | 应对 |
|---|---|
| 日线级方向预测信噪比极低（知识库已记录），再强的模型也难「准」 | 体检报告 + 评分把「不准」诚实暴露出来，工具价值在「可信地告诉你模型行不行」，而非许诺收益 |
| LightGBM 引入新依赖 | CPU 无 GPU 依赖、pip 单包安装，风险低；不可用时优雅降级回 torch 模型 |
| walk-forward 训练耗时长 | 默认段数保守（3-5 段），后台队列 + 进度反馈 |
| 多标的组合回测改动撮合核心 | 放在 M2 最后一项，先保单标的正确性 |
